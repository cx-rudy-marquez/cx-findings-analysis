How re-onboarding works Beta

{% if run.reonboard_status == "completed" %}

Already re-onboarded. The repository now scans through {{ run.fa_project_name }}, and {{ run.source_project_name }} was kept as a manual project with its full scan history. See exactly what was done.

{% elif not parity %}

This run has no parameter parity check, so its comparison has not been shown to be attributable. Re-run the comparison before re-onboarding.

{% else %}
  1. The original is disconnected from its repository. It keeps every scan it has ever run and becomes a manual project.
  2. It is renamed to {{ run.source_project_name }}_FA_BACKUP, freeing its name.
  3. The copy is renamed to {{ run.source_project_name }}, taking that name over.
  4. The copy is connected to the repository in the original's place, and that same call scans the branch the baseline ran on — the conversion triggers the scan itself, so there is no separate follow-up.

A project connected to no repository skips straight to the two renames and the rescan: there is nothing to disconnect and nothing to connect to.
